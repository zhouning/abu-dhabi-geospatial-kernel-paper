# 阿布扎比 Geospatial Kernel 与完整 GWM 架构的能力边界说明

## 1. 结论

严格来说，阿布扎比并不是“不能”实现到 GWM 理论图中的程度，而是当前公开数据、客户已提供的信息和现有 Abu Dhabi benchmark 实现，尚不足以支撑完整实现及其科学验证。

需要区分三个层面：

1. 软件上能否编写相应模块；
2. 数据上能否为这些模块提供可靠输入；
3. 科学上能否验证模块有效，并据此提出可信结论。

目前主要限制在后两项，而不是算法代码本身无法扩展。

## 2. 当前 Abu Dhabi Kernel 的实际实现

当前实现将一个模拟步骤拆分为“转移提议—约束投影—状态写回”：

```text
当前状态 S_t + 外生变量 X_t
          ↓
HistGradientBoostingClassifier
          ↓
概率提议 Q_t(i,c)
          ↓
动作 A_t 的目标类别数量
+ 硬约束 C
          ↓
constraint projection / allocate_action
          ↓
下一状态 S_{t+1}
```

对应公式为：

\[
Q_t(i,c)=p_\theta(c\mid S_t,X_t)
\]

\[
S_{t+1}=\Pi_{\mathcal C,A_t}(Q_t,S_t)
\]

其中：

- (Q_t) 是模型根据当前土地覆盖状态、邻域特征和外生变量提出的像元级转移概率；
- (A_t) 是规划者提供的目标类别数量或可行需求；
- (\Pi) 根据目标数量、硬约束和候选评分，决定哪些像元真正发生变化。

因此，当前 Abu Dhabi adapter 中的动作并不进入概率提议模型，而是在后续约束投影阶段发挥作用。

当前实现已经具备：

- typed state、typed action 和时间一致性检查；
- 像元级转移概率提议；
- 目标类别数量约束；
- 硬排除区域保护；
- 约束不可满足时的 fail-closed 行为；
- 状态递归写回；
- provenance、审计和可复现性记录。

但这属于 Geospatial Kernel 的一个受限土地覆盖适配器，不等于完整 GWM 理论图中的所有能力都已经实现。

## 3. 为什么目前不能直接达到理论图的完整程度

### 3.1 动作条件化转移缺少真实训练样本

理论图中通常表达：

\[
S_{t+1}=\Phi_G(S_t,A_t,\Gamma_t,Y_t,\text{lag})
\]

这意味着动作 (A_t) 直接影响状态转移过程，并且模型能够学习“采取某种规划动作后，空间状态如何变化”。

要实现这一点，至少需要多年度配对数据：

```text
规划或审批动作
        ↓
建设、改造、保护或基础设施实施
        ↓
后续土地覆盖/土地利用变化
```

当前 Abu Dhabi benchmark 中的动作主要是合成的年度类别数量目标，例如增加多少建成像元或绿色像元。它们不是历史规划部门实际执行的动作，也没有与真实建设结果形成可靠的动作—结果配对样本。

因此可以编写一个 action-conditioned 网络，但不能据此声称已经学习到了真实政策动作对城市变化的因果或结构性影响。

### 3.2 缺少显式空间骨架 (G)

理论图中的 (G) 通常可以理解为显式空间图或城市系统拓扑，包括：

- 地块及地块邻接关系；
- 道路等级和连通性；
- 公共交通和基础设施网络；
- 行政边界、规划单元和服务区；
- 水系、生态廊道和保护边界；
- 地块之间的开发依赖关系。

当前实现主要使用：

- 100 m 栅格；
- 3×3 和 7×7 邻域比例；
- 坐标、高程、坡度；
- 距道路和主干路距离；
- 夜间灯光等公开驱动变量。

这些变量提供了隐式空间上下文，但不是显式的城市空间图，也没有实现图神经网络或网络级传播机制。因此当前只能说模型使用了局部空间特征，而不能说已经实现了完整的 (G) 图结构。

### 3.3 缺少可估计的时间滞后动力学

理论图中的 `lag` 表示规划动作、基础设施建设、项目施工和最终地表变化之间可能存在多年滞后。

要估计这种机制，需要至少包含以下时间信息：

- 项目批准时间；
- 开工时间；
- 竣工时间；
- 土地用途或建筑用途变更时间；
- 基础设施投运时间；
- 拆除、更新或再开发时间。

当前数据主要是年度土地覆盖栅格。它可以支持年度状态递归，但不能可靠地估计审批—施工—建成之间的时滞分布，也没有单独的滞后状态变量或时滞转移模块。

因此，当前实现中的“多年度”主要是递归 rollout，而不是已经识别出真实城市发展滞后机制的动态模型。

### 3.4 公开土地覆盖产品不能承担在线观测同化

理论图中的 (Y_t) 表示持续到来的观测，并可用于纠正当前状态或模型信念，例如：

```text
影像观测 Y_t
        ↓
状态估计/变化检测
        ↓
更新 S_t 或模型 belief
```

当前 benchmark 使用的公开年度产品存在明显标签噪声和年度不稳定性。它们主要用于：

- 构造历史训练样本；
- 计算样本权重；
- 进行事后评价；
- 生成公开数据条件下的压力测试结果。

这些产品没有被作为在线观测同化模块使用，也没有实现 Bayesian、Kalman 或其他明确的数据同化机制。

高分辨率 ArcGIS 影像可以改善地物观测质量，但仅能主要改善 (Y_t)。它不能自动提供真实规划动作、法定约束、基础设施容量或动作后果，因此单独提高影像分辨率并不能使系统达到完整 GWM 架构。

### 3.5 缺少权威规划约束 \(\Gamma_t\)

理论图中的约束通常应当是具有法律、规划或运营含义的约束，例如：

- 法定土地利用分区；
- 已批准和待批准项目；
- 生态红线和保护区；
- 水域、湿地和海岸带管理边界；
- 地块权属和开发权限；
- 建筑密度、容积率和高度限制；
- 道路、供水、供电和污水等基础设施容量；
- 灾害、洪涝和环境风险限制。

当前实现中的约束主要来自公开 WorldCover、OSM 和栅格化代理图层。它们可用于公开数据基准中的硬排除测试，但不是阿布扎比法定规划边界，也不能代表客户内部的开发许可和基础设施容量。

因此当前的约束投影可以保证“公开代理条件下的可行性”，不能宣称保证“真实规划制度下的合法性或可实施性”。

### 3.6 缺少真实反事实验证

完整 GWM 图通常包含未来分支、反事实分支和决策反馈。要验证这些能力，需要历史上真实发生过的不同规划方案，或者至少有可追溯的政策干预和结果数据。

当前 Abu Dhabi benchmark 的场景动作是规划者提供的合成压力测试输入。它可以回答：

> 在给定公开数据、目标数量和代理约束下，不同模型会产生怎样的空间分配结果？

但不能回答：

> 如果阿布扎比实际采取某项规划政策，未来真实城市状态一定会如何变化？

后一个问题需要真实的政策—实施—结果链条，目前尚未具备。

### 3.7 生产级 current/shadow 和 evidence gate 仍不是完整系统

理论图中的 current/shadow、evidence gate、issue-time vintage 和多系统复现，属于平台级生产治理能力。它们通常需要：

- 当前生产状态与候选状态的双轨存储；
- 数据和模型版本的时间冻结；
- 新证据的准入规则；
- 多系统独立验证；
- 失败回滚和审批记录；
- 面向生产服务的权限、审计和发布流程。

当前仓库已经有 provenance、manifest、审计、哈希和 fail-closed 检查，但这些是可复现研究运行时契约的实现，不等于已经部署了完整的城市规划生产准入系统。

## 4. 当前实现与理论图的边界

| 理论图中的能力 | 当前状态 | 结论 |
|---|---|---|
| 动作直接进入状态转移 | 动作在约束投影阶段使用 | 部分实现，机制不同 |
| 显式空间图 (G) | 使用栅格邻域和道路距离 | 仅有隐式空间上下文 |
| 时间滞后 dynamics | 有年度递归写回 | 没有独立时滞模型 |
| 观测 (Y_t) 闭环 | 公开标签用于训练和评价 | 没有在线观测同化 |
| 权威约束 (\Gamma_t) | 使用公开代理掩膜 | 不是法定规划约束 |
| 反事实未来分支 | 有合成情景压力测试 | 不是经过现实验证的预测 |
| current/shadow、evidence gate | 有审计和 provenance | 尚非完整生产治理系统 |
| 状态写回 | 已实现 | 与理论图一致 |
| 约束失败关闭 | 已实现 | 与理论图一致 |

## 5. 这不是阿布扎比地区本身的限制

阿布扎比并非在技术上无法实现完整架构。真正的限制是：

```text
公开栅格数据
    ≠ 权威土地利用数据库

高分辨率影像
    ≠ 规划动作和政策结果数据

年度地表标签
    ≠ 完整城市发展动力学

合成场景目标
    ≠ 真实决策干预
```

如果客户能够提供权威本地数据，并允许进行必要的数据处理，系统可以逐步向理论图扩展。但扩展之后还需要独立验证，不能仅凭软件模块已经运行就宣称模型已经正确描述真实城市系统。

## 6. 达到理论图程度的实施路线

### 第一阶段：权威状态数据

- 高分辨率、多年度正射影像；
- 建筑物、道路、水体和绿地的权威矢量或栅格数据；
- 地块和规划单元边界；
- 统一坐标、时间和质量元数据；
- 逐年变化标签和人工核验样本。

### 第二阶段：权威动作与约束数据

- 土地利用规划和分区；
- 项目审批、开工、竣工和拆除记录；
- 基础设施建设和投运记录；
- 生态和环境保护边界；
- 道路、供水、供电和污水容量；
- 地块开发权限与状态。

### 第三阶段：模型扩展

- action-conditioned transition model；
- 显式地块—道路—设施空间图；
- 多尺度图消息传递或图时空模型；
- 显式施工和开发时滞状态；
- 观测同化和不确定性更新；
- 面向不同规划动作的反事实分支。

### 第四阶段：验证与生产治理

- 历史规划方案回放；
- 留出年份和留出区域验证；
- 真实建设项目级验证；
- 多系统独立复现；
- current/shadow 状态管理；
- evidence gate 和版本准入；
- 失败回滚和审计闭环。

## 7. 对论文和客户沟通的准确表述

当前论文应表述为：

> The Abu Dhabi benchmark implements a bounded proposal–projection–writeback adapter of the Geospatial Kernel. The full action-conditioned, observation-assimilating and graph-structured GWM architecture remains an engineering and validation roadmap, rather than an established result of this benchmark.

中文可表述为：

> 本研究在阿布扎比公开数据基准中实现了 Geospatial Kernel 的受限“转移提议—约束投影—状态写回”适配器。完整的动作条件化、观测同化和显式空间图结构 GWM 架构仍属于后续工程实现与验证路线，不能视为本基准已经证明的结果。

因此，之前的两张图可以保留为 GWM 的理论或平台级概念图，但不应被解释为当前 Abu Dhabi benchmark 已逐项实现的技术流程图。论文正文应以 proposal–projection–writeback 图和实际代码为准。
